## 二、这意味着什么

### 两颗芯片已经能对话，但 PC 是聋子

OpenMV 与 F407 之间是 USART3 硬连线，**开机就会自动开始握手**：

1. F407 上电主动发 `READY`
2. OpenMV 发 `PING`，F407 回 `PONG`
3. 之后持续交互：`PS<speed>` / `TA<deg>` / `FIRE<ms>` / `STOP`

**这套链路本身不依赖 PC。** PC 现在只能通过 COM4 听到 OpenMV 的
`print()` 输出，**听不到 F407 说的话，也不能给 F407 下命令。**

### 安全现状（好消息）

```python
LASER_DRY_RUN = True     # OpenMV main.py:145
```

OpenMV 只发「申请点射」，F407 收到 `FIRE<ms>` 后按自身时序驱动激光。
**当前 DRY_RUN=True，实际不会出光。** 可以放心调试。

### 已确认的协议（V1.1，2026-09-13 定版）

**OpenMV → F407**（粘连式，**不是逗号式**）

| 命令 | 含义 |
|---|---|
| `PING` | 心跳，**间隔必须 < 1.5 s** |
| `PS<speed>` | pan 速度 -100..100，0=停 |
| `TA<deg>` | tilt 角度 0..180 |
| `S3A<deg>` `S4A<deg>` | 备用舵机 |
| `FIRE<ms>` | 申请点射 1..2000 |
| `L0` | 主动关激光 |
| `STOP` | 急停 |

**F407 → OpenMV**：`READY` / `OK` / `ERR` / `PONG`

> ⚠️ **粘连式是硬约束**：F407 用 `atoi(line+4)` 解析。
> 发 `FIRE,300,1` 会解析成 `atoi(",300,1") == 0` → 判非法 → 回 `ERR` 且**不开火**。

> ⚠️ **看门狗硬约束**：`OPENMV_LINK_WATCHDOG_MS = 1500ms`。
> 连续 1.5 s 没收到合法帧，F407 强制 pan 停 + 关激光。
> OpenMV 固件因此保证任何状态下最长间隔 < 1.4 s。

## 三、PC 侧现在能做什么 / 不能做什么

| 动作 | 现状 |
|---|---|
| 监听 OpenMV 串口输出（COM4） | ✅ 可以 |
| 读写 OpenMV 固件（J 盘） | ✅ 可以 |
| 给 F407 下命令 / 收 F407 应答 | ❌ 不行 |
| 读写 F407 寄存器 | ❌ 不行（ST-Link 驱动缺失） |
| 通过 F407 的 USB 虚拟串口 | ❌ F407 没有这个口 |

### 想看到 F407 的运行时状态，三条路

| 方案 | 做法 | 代价 |
|---|---|---|
| **A. 从 COM4 间接看**（推荐先做） | OpenMV 固件里把 F407 的应答原样 `print()` 出来，PC 从 COM4 读 | **零硬件改动**，只需改 OpenMV 固件 |
| **B. 加一根 USB 转 TTL** | 接到 F407 的空闲 USART 或 SWO 脚 | 需要硬件，但 PC 就能直连 F407 |
| **C. 装 ST-Link 驱动** | 装 CubeProgrammer / STSW-LINK009 | 能读写 Flash 和寄存器，但拿不到串口日志 |

> **A 是最现实的**：不动硬件，改 OpenMV 固件让它把 F407 的应答透传出来。
> 这只需要几分钟，而且能立刻看到两颗芯片的完整对话过程。

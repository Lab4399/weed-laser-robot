## 二、F407 里现在跑的是什么

### 2.1 已不是 GoodDog 了

| | 烧录前 | 现在 |
|---|---|---|
| 固件 | GoodDog（交付包 9-28 那版，34 996 B） | **新应用层固件 fw407（20 756 B）** |
| 视觉链路 | USART3 / PD8 / PD9 | **USART1 / PA9 / PA10**，115200 |
| 协议 | 粘连式 `PING` / `PS<speed>` / `TA<deg>` / `FIRE<ms>`（V1.1） | **`@T,seq,CLS,conf,x,y,w,h,flags*crc`** |
| 状态机 | 无 | INIT → IDLE → AUTO / SAFE_STOP / FAULT |
| 看门狗 | — | IWDG 500 ms，唯一喂狗点在 `safety_tick_1ms()` |

> 协议换了是**关键变化**：老的 `PING/PS/TA/FIRE` 那套现在是无效的，
> 与新固件对不上。新协议是 ASCII 行帧，CRC-8（poly 0x07）校验，
> 两侧算法已经用 5 组测试向量交叉验证过（含 `@T,104,WEED,0.88,...` → CRC `0x6C`）。

### 2.2 运行时实测

```
s_state     = 1 (IDLE)         fault = 0 (NONE)
uptime      = 60994 → 61502 ms 连续增长（脱机、无调试器介入）
streak      = 0                三路心跳 [61501, 61501, 61501] 全部新鲜
USART1_CR1  = 0x0000201C       UE/TE/RE/IDLEIE 全开
USART1_BRR  = 0x000002D9       115200 @ 84 MHz APB2
TIM3/TIM4   = 0x00000081       CEN=ON（舵机 50 Hz / 电机 PWM）
ul_dma_err  = 0
```

**上电姿态是安全的**：`SYS_IDLE` 下 `motor_enable(false)`、两路 PWM 占空比为 0、
`motion_request_stop()`。上电不会驱动任何执行器。

### 2.3 第一次烧录踩的坑

刚烧完是"每 500 ms 复位一次、串口零输出"。查出来是 6 个叠在一起的固件缺陷
（FAULT 自锁复位环、`HB_CONTROL` 从未被喂、视觉心跳绑在收帧上、时基不同源、
初始化不进 IDLE、DMA 重复启动）。

完整分析见 **[F407固件构建与烧录.md](F407固件构建与烧录.md) 第四节**。
修完后 60 秒生存测试通过。

## 三、两颗芯片为什么还没在对话

**因为线还没接。** 这不是软件问题。

新固件把 USART1 配置好了（`UE=ON, TE=ON, RE=ON, IDLEIE=ON, DMAR=ON`），
DMA 已在循环接收，但 `ul_bytes_rx = 0`、`vp_frames_ok = 0` —— 一个字节都没进来。

同时 OpenMV 侧也还没在跑：`main_diag.py` 已写进 J 盘，但**烧完必须物理拔插
一次 USB**（OpenMV 写完文件不会自动重启，Ctrl-D 软复位也无效），
否则 J 盘持续挂载、固件根本不执行，COM4 全程静默。

### 接线表

| F407 | 方向 | OpenMV |
|---|---|---|
| **PA9** (USART1_TX) | → | **P5** (UART3 RX) |
| **PA10** (USART1_RX) | ← | **P4** (UART3 TX) |
| GND | — | GND |

> ⚠️ 老固件用的是 PD8/PD9，机箱里现成的线如果是接在那两个脚上，**要挪到 PA9/PA10**。
> ⚠️ TX/RX 必须交叉，且必须共地。

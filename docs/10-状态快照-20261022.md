## 四、F407 侧配置（首次确认）

之前因为缺工具读不到，这次从源码拿到。

### 视觉链路

| 项 | 值 |
| --- | --- |
| 串口 | USART1 @ **PA9(TX) / PA10(RX)** |
| 波特率 | 115200 |
| DMA | RX=DMA2 Stream2 Ch4，TX=DMA2 Stream7 Ch4 |
| `LINK_IMG_WIDTH` | 320（与 OpenMV 一致 ✓） |
| `LINK_TIMEOUT_MS` | **600** |
| `LINK_TIMEOUT_DEGRADE_MS` | **900**（超过进 SAFE_STOP） |

**由此推出硬指标**：注释要求 `LINK_TIMEOUT_MS > 单帧推理最坏耗时 × 1.5`
→ **推理最坏耗时必须 < 400ms**

> 注意：OpenMV 的心跳虽设 50ms，但主循环被推理阻塞时发不出去。
> 所以 600ms 这个值实际约束的是「单次推理耗时」，不是心跳周期。

### 执行器

| 项 | 值 |
| --- | --- |
| 电机 PWM | TIM4 CH1~CH4 @ **PB6~PB9**，20 kHz |
| 舵机 PWM | TIM3 CH1/CH2 @ **PA6/PA7**，50 Hz |
| 舵机数量 | 2（执行机构） |
| 舵机脉宽 | 1000~2000 µs（SG90 保守范围） |
| 上电缓动 | 10 µs / 10 ms 步进 |

### 控制参数（全部待实车标定）

```
CTRL_PERIOD_MS      10      控制周期 100Hz
CTRL_BASE_SPEED     350     基础速度（千分比）
CTRL_KP_TURN        1.2     转向比例
CTRL_CENTER_DEADZONE 20 px  转向死区
CTRL_SLEW_STEP      35      加速度限制 ← 注释说"比 Kp 更重要"
MOTOR_DEADZONE_DUTY 60      电机启动死区补偿
```

### 安全

```
SAFETY_CONF_MIN       0.55   低于不允许激进运动
SAFETY_CONF_DEGRADE   0.75   低于主动降速
SAFETY_LOST_FRAMES_SLOW 10   丢 10 帧减速
SAFETY_LOST_FRAMES_STOP 40   丢 40 帧停车搜索
SAFETY_IWDG_TIMEOUT   500ms  独立看门狗
```

FreeRTOS 5 个任务：safety(10) / control(8) / vision(6) / motion(5) / param(2)。

参数持久化用 Flash sector 10/11 双 bank。

## 六、一处需要澄清的误解：舵机其实不冲突

OpenMV `config.py` 的注释说：

> 「F407 侧 TIM3 也在输出 50 Hz 舵机 PWM。在接线未核实之前让 OpenMV 同时驱动 pyb.Servo，等于两个主控争同一路信号」

但 F407 `app_config.h` 明确写了控制权归属：

```
履带电机 2 路    → F407 控制
执行机构舵机 2 路 → F407 控制
摄像头云台舵机    → OpenMV 控制（不在本固件范围内）
```

**TIM3 @ PA6/PA7 是「执行机构舵机」，不是摄像头云台。** 两者是不同物理舵机，文档上不冲突。

所以 `GIMBAL_ENABLE = False` 是基于不完整信息做的保守判断。现在可以：
1. 确认摄像头云台舵机**物理上**接在 OpenMV 的舵机口（`pyb.Servo(1)` 对应哪个引脚）
2. 确认后把 `GIMBAL_ENABLE` 改回 `True`，云台闭环才能工作

⚠️ 但如果实测发现云台信号线确实接到了 PA6/PA7，那就是接线问题，需要改线而不是改配置。

## 八、下一步（按阻塞程度排序）

1. **拿模型**（唯一硬阻塞）
   需要 FOMO 检测模型（`tf.detect` 输出多框），不是分类模型。

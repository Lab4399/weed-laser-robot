# F407 连接失败诊断报告

> 时间：2026-10-23 19:30
> 现象：读取 F407 芯片时电脑连不上
> 结论：**ST-Link 与板子大概率正常，是工具缺少设备数据库**

---

## 一、实测证据

### ST-Link 这一层完全正常

```
ST-LINK SN  : 37FF71064E573436035C1043
ST-LINK FW  : V2J48S7
Board       : --
Voltage     : 3.30V          ← 能读到电压，说明 USB 通信正常
SWD freq    : 4000 KHz
```

能读到序列号、固件版本、电压，说明：
- USB 线是好的（不是只能充电的线）
- ST-Link 驱动正常
- ST-Link 自身固件正常
- SWD 连接器上有 3.3V

### 但报错指向工具本身

```
Error: Unable to list supported devices
Error: Cannot identify the device
```

**关键观察**：三种连接模式报的错**完全相同**：

| 模式 | 参数 | 结果 |
| --- | --- | --- |
| 普通 | `-c port=SWD` | 同上两个错误 |
| 复位下连接 | `-c port=SWD mode=UR` | 同上两个错误 |
| 降频 | `-c port=SWD freq=1000` | 同上两个错误 |
| 热插拔 | `-c port=SWD mode=HOTPLUG` | 同上两个错误 |

如果是 SWD 通信问题，`mode=UR`（复位期间抓内核）通常会有不同表现。
**四种模式报同一个错，说明根本没走到 SWD 通信那一步。**

### 检查工具目录：缺设备数据库

当前使用的 CLI 来自 OpenMV 扩展：

```
C:\Users\Administrator\.vscode\extensions\singtown.openmv-2.5.1-win32-x64\
  tools\stcubeprogrammer\windows\
    ├── STM32_Programmer_CLI.exe   5.1 MB
    ├── STLinkUSBDriver.dll
    ├── Qt6Core.dll / Qt6Qml.dll / ...
    └── JLink_x64.dll
```

**没有 `Data_Base` 目录**。

完整版 STM32CubeProgrammer 的结构是：

```
STM32CubeProgrammer/
├── bin/STM32_Programmer_CLI.exe
└── Data_Base/
    ├── STM32_Device.db      ← 设备数据库，缺这个就认不出芯片
    ├── STM32_Flash.db
    └── ...
```

全盘搜索确认：**系统里没有任何 `STM32_Device.db` 或 `Data_Base` 目录**。

`AppData\Local\stm32cube\bundles\` 里只有 JRE、CMake、stlink-server，**没有 CubeProgrammer**。

## 二、结论

**`Unable to list supported devices` 的意思是"列不出支持的设备清单"，不是"连不上芯片"。**

工具能连上 ST-Link（所以读到了 SN 和 3.3V），但查不到"STM32F407 是什么芯片、Flash 多大、寄存器在哪"，所以下一步必然失败，报 `Cannot identify the device`。

**这不是你板子的问题。**

---

## 三、解决办法

### 方案 A（推荐）：装完整版 STM32CubeProgrammer

1. 去 ST 官网下载（需注册账号）：
   `https://www.st.com/en/development-tools/stm32cubeprog.html`
2. 安装（默认路径即可，会自带 Data_Base）
3. 验证：
   ```cmd
   "C:\Program Files\STMicroelectronics\STM32Cube\STM32CubeProgrammer\bin\STM32_Programmer_CLI.exe" -c port=SWD
   ```
   成功时应该看到：
   ```
   Device ID   : 0x413
   Device name : STM32F405xx/F407xx/F415xx/F417xx
   Flash size  : 1 MBytes
   ```

### 方案 B：装完整版 STM32CubeIDE

体积更大，但包含 CubeProgrammer 全套（含 Data_Base），且能直接编译你 `E:/PlantDiseaseProject/_f407build/` 的工程。

### 方案 C：用 VS Code 扩展

你已装 `stmicroelectronics.stm32cube-ide-core`，但实测其 bundle 里也只有 stlink-server，没有设备数据库。**这条路大概率同样失败**，除非扩展在首次连接时自动下载工具链。

## 四、装好后的验证与排查

### 第一步：确认能识别芯片

```cmd
STM32_Programmer_CLI.exe -c port=SWD
```

**看到 `Device name : STM32F405xx/F407xx...` 就成功了。**

### 第二步：如果仍然失败，按这个顺序查

| 顺序 | 检查项 | 判断方法 |
| --- | --- | --- |
| 1 | **目标板是否独立供电** | F407 板必须有外部电源。ST-Link 的 3.3V 输出带不动整板 + 外设。用万用表测板上 3.3V 和 5V 是否有电 |
| 2 | **SWD 四线是否接全** | SWDIO→PA13、SWCLK→PA14、**GND 必须接**、3.3V 可选。GND 没接是最常见的隐蔽故障：电压能测到，但通信不通 |
| 3 | **是否读保护（RDP）** | 如果之前烧过带 RDP Level 1 的固件，SWD 会被限制。用 `-c port=SWD mode=UR` 试，或全片擦除 |
| 4 | **BOOT0 引脚状态** | BOOT0 拉高会进 System Memory，正常应从 Flash 启动（BOOT0=0） |
| 5 | **芯片是否跑飞** | 用 `mode=UR` 在复位期间抓。若 UR 能连而 Normal 不能，说明固件把 PA13/PA14 复用掉了 |
| 6 | **换一根 USB 线** | 有些线只供电不传数据。虽然当前能读 SN，但如果换过线要重新确认 |

### 第三步：读回固件备份

连上后第一件事（重要）：

```cmd
STM32_Programmer_CLI.exe -c port=SWD -upload 0x08000000 0x100000 firmware_backup.bin
```

F407 有 1MB Flash，这条命令把整片读回来存成 `firmware_backup.bin`。
这样即使后面误烧，也能恢复。

## 五、两个附带提醒

### 1. ST-Link 当前被占用

```
进程 stlinkserver.exe (PID 22420) 监听 127.0.0.1:7184，且有活跃连接
进程 cube.exe (PID 13236) 是 VS Code 的 STM32 扩展
```

ST-Link 是独占资源。如果装好 CubeProgrammer 后报 `ST-LINK is already in use`，
先关掉 VS Code 的调试会话（或整个 VS Code），再连。

不过当前报的不是占用错误，所以**占用不是本次失败的原因**。

### 2. 3.30V 不能证明板子已上电

ST-Link 报的 `Voltage: 3.30V` 可能是：
- 目标板自己的 3.3V（正常情况）
- ST-Link 输出的 3.3V（如果目标板没供电，ST-Link 的 3.3V 引脚会"顶"着）

所以不要仅凭这个值判断板子通电。**用万用表实测板上 3.3V 和 5V 更可靠。**

## 六、一句话总结

> ST-Link 好的、线大概率也是好的、板子大概率也是好的。
> 缺的是 STM32CubeProgrammer 的 `Data_Base` 设备数据库，
> 装个完整版就能解决。装完先做 `-upload` 备份固件。

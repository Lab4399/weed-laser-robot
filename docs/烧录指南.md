# STM32F407 烧录指南

面向实验室同学，讲清楚「芯片插上了但烧不进去」这件事该怎么看、怎么做。

---

## 一、当前诊断结论（2026-10-19 实测）

###芯片硬件是好的，驱动没装

| 检查项 | 结果 |
|---|---|
| ST-Link 是否被系统识别 | ✅ **已识别** —— `VID=0483 PID=3748`（ST-Link V2） |
| 驱动状态 | ❌ **`CM_PROB_FAILED_INSTALL`** |
| 烧录工具 | ❌ STM32CubeProgrammer / OpenOCD / JLink 全部未安装 |
| 目标芯片 | **STM32F407ZGT6**（LQFP144，1 MB Flash / 192 KB RAM） |

**`CM_PROB_FAILED_INSTALL` 是根因**：Windows 认得这块硬件，但装不上它的驱动，
所以任何烧录软件都无法与 ST-Link 通信。**这不是固件问题，也不是接线问题。**

> ⚠️ 常见误判：看到设备管理器里有个带黄色感叹号的 "STM32 STLink"，
> 很多人以为是芯片坏了。**实际上是驱动缺失，硬件本身没问题。**

## 二、需要你先装两样东西

### 【第1 步】装 STM32CubeProgrammer（推荐，一包搞定驱动+工具）

下载地址（官方）：<https://www.st.com/en/development-tools/stm32cubeprog.html>
中文页：<https://www.st.com.cn/zh/development-tools/stm32cubeprog.html>

- 免费，ST 官方
- **自带 ST-Link 驱动**，装完这两样问题一次解决
- 提供 GUI 与 CLI 两个版本，本项目用的是 CLI：
  `C:\Program Files\STMicroelectronics\STM32Cube\STM32CubeProgrammer\bin\STM32_Programmer_CLI.exe`
- ⚠️ **下载需要登录 ST 账号**（免费注册，邮箱验证即可）

### 【第 2 步】（可选）只装驱动

如果不想装整个 CubeProgrammer，只装驱动：

**STSW-LINK009** —— <https://www.st.com.cn/zh/development-tools/stsw-link009.html>
（英文页：<https://www.st.com/en/development-tools/stsw-link009.html>）

- 约 5 MB，是 ST-LINK/V2 的 USB 签名驱动
- 官方文档明确写了：**「连接 ST-LINK/V2 或 ST-LINK/V2-1 器件前必须安装驱动才能正确枚举」**
  —— 这正是你现在遇到的情况
- 支持 Windows 10/11 的 x86 与 amd64，**数字签名驱动**

> ⚠️ **注意**：只装驱动能解决「设备管理器里 STLink 带感叹号」的问题，
> 但**不能烧录**。真正烧录还需要 CubeProgrammer（或 OpenOCD / J-Link 等）。
> 建议直接装 CubeProgrammer，一次到位。

> **Windows 安全提示**：安装时如果弹出「Windows 已阻止安装未经签名的驱动程序」，
> 选 **「仍然安装」/「Override」**。ST 的驱动有时被 Windows 误判。

### 本机环境（已核实）

| 项 | 值 | 是否兼容 |
|---|---|---|
| 操作系统 | Windows 10 专业版 64 位（构建 19045） | ✅ 驱动支持 Win10 x64 |
| ST-Link 标识 | `USB\VID_0483&PID_3748` | ✅ ST-Link V2，配 STSW-LINK009 |
| 目标芯片 | STM32F407ZGT6（LQFP144，1 MB Flash） | — |

> 你的 ST-Link 是 **V2**（PID=3748），STSW-LINK009 正好覆盖。

## 三、装完之后

回来告诉我一声，我用这个命令自检：

```bash
python _toolchain\flash_f407.py --check
```

它会分三层检查并直接告诉你结论：驱动是否正常、工具是否找到、能不能连上芯片。

## 四、正式烧录流程

### 第 1 步：先读芯片信息（安全，不写入）

```bash
python _toolchain\flash_f407.py --info
```

读取 `SCB->CPUID` 和 Flash size 寄存器，确认：
- 能连上芯片（SWD 协议通了）
- 芯片型号对不对
- Flash 容量是不是 1 MB

### 第 2 步：⚠️ 必须先备份

```bash
python _toolchain\flash_f407.py --backup
```

会把芯片当前 1 MB Flash 完整读出，存到 `models/f407_backup_<时间戳>.bin`。

**烧录是破坏性操作，会覆盖现有固件。** 这块 F407 上可能有交付包之外的
现场调试代码，备份完再烧，出问题才能退回去。

### 第 3 步：烧录

```bash
python _toolchain\flash_f407.py --flash "<镜像路径>"
```

脚本会要求输入 `yes` 二次确认才真正写入。

## 五、⚠️ 该烧哪个镜像？先问清楚

交付包里这四个文件**不是随便挑一个烧的**：

| 文件 | 大小 | 说明 |
|---|---|---|
| `f407_current_20260928_含GoodDog.bin` | 1 MB | 含 GoodDog 的**当前固件全片镜像** |
| `f407_firmware.hex` | 98 KB | Intel HEX，**带明确地址信息** |
| `f407_firmware_35KB.bin` | 35 KB | 仅前 35 KB，看起来像应用区段 |
| `f407_flash_1MB.bin` | 1 MB | 从芯片读出的 dump，通常**不需要烧回去** |

所在目录：
```
02_单片机固件\小车_完整备份\01_F盘小车备份原包\3备份F407\01_芯片固件镜像\
```

**交付包里没有说明哪个是「芯片上现在正在跑的」**，也没有说明这几个文件的关系。
我**不替你判断** —— 烧错固件小车会直接不能动。

**请找实验室同学确认：**
1. 芯片上现在跑的是哪个版本？
2. 这次要改成哪个版本？
3. 改动的部分是什么（GoodDog 行走控制？激光时序？还是别的）？

确认清楚了我再执行。稳妥的做法是：**先用 `--info` 读出芯片信息存档，
再用 `--backup` 完整备份，然后烧录确认过的镜像，烧完立刻测试基本动作。**

## 六、常见故障

| 现象 | 原因 | 处理 |
|---|---|---|
| 设备管理器「STM32 STLink」带黄色感叹号 | 驱动未安装 | 装 CubeProgrammer 或 STSW-LINK009 |
| CubeProgrammer 连不上，报 `No STLink detected` | 驱动装好但线/口有问题 | 换USB 线（有些只供电不通信）、换 USB 口、SWD 频率降到 100 kHz |
| 连上了但 `Read operation failed` | 可能进了低功耗模式 / 被读保护 | 用 `--connect UNDERLAY` 试试 |
| 烧录后程序不跑 | 可能是程序没复位 / 看门狗 | 脚本已加 `-rst`；仍不行检查 BOOT0 引脚 |
| 需要改代码重新编译 | Good_Dog 是 CubeMX 工程 | 用 STM32CubeIDE 打开 `Good_Dog.ioc` 编译，产物在 `Debug/` |

### SWD 频率降频

信号不稳时降低频率：

```bash
python _toolchain\flash_f407.py --info --freq 100     # 降到 100 kHz
```

默认 4000 kHz。不稳就一路降到 100。

```
02_单片机固件\小车_完整备份\01_F盘小车备份原包\3备份F407\04_GoodDog工程\Good_Dog\
├── Core/                    源代码

├── STM32F407ZGTX_FLASH.ld   链接脚本
├── STM32F407ZGTX_RAM.ld
└── Debug/                   编译产物（Good_Dog.bin / .hex）
```

**要改固件代码**的话，用 STM32CubeIDE 打开 `Good_Dog.ioc`，
选择对应工具链（MDK-ARM 或 GCC）后编译。

芯片信息已确认：
- `Mcu.CPN = STM32F407ZGT6`
- `Mcu.Package = LQFP144`
- `ProjectManager.DeviceId = STM32F407ZGTx`

## 八、本工具做的事

`_toolchain/flash_f407.py` 只是把命令行封装成有检查、有确认、有备份的流程，
底层调用的还是 ST 官方的 `STM32_Programmer_CLI.exe`。

**它不做什么**：
- 不替你选固件镜像
- 不自动备份（要你显式敲 `--backup`）
- 不绕过读保护

**它做什么**：
- 分层体检：驱动 / 工具 / 芯片，逐层定位问题
- 破坏性操作前二次确认
- 输出可读的命令行结果，而不是让你盯一堆英文 log
